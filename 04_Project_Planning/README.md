# Phase 4 – Project Planning & Scheduling

## 4.1 Project Planning

CRICKSTATS follows an Agile-based project execution approach.

The project is planned in sprint-wise development stages covering:

- Object Creation
- Automation
- Reporting
- Testing and Validation

## 4.2 Product Backlog

| Sprint | Requirement | User Story | Points | Priority | Team Member |
|---|---|---|---:|---|---|
| Sprint-1 | Developer Setup | As a user, I want a Salesforce developer account so that I can develop the application. | 1 | High | Member1 |
| Sprint-1 | Data Modeling | As a system, I want Player and Match Performance objects so that player performance data can be stored. | 3 | High | Member2 |
| Sprint-2 | Navigation | As a user, I want separate tabs for each object so that I can easily access the data. | 3 | High | Member3 |
| Sprint-2 | UI Design | As a user, I want a dedicated Lightning App so that I can access the application features from one place. | 3 | High | Member4 |
| Sprint-2 | Data Structure | As a system, I want player and match fields so that required information can be stored. | 5 | Medium | Member1 |
| Sprint-2 | Data Structure | As a user, I want customized page layouts so that records are easy to view and manage. | 5 | High | Member2 |
| Sprint-2 | Automation | As a system, I want to validate player and match inputs so that incorrect data can be prevented. | 3 | High | Member4 |
| Sprint-3 | Automation | As a system, I want automated flows to update player statistics so that performance data remains accurate. | 5 | High | Member1 |

## 4.5 Planning Approach

The project development is organized into sprint-wise activities. Each sprint focuses on specific development tasks, starting with the Salesforce setup and data model and progressing toward navigation, user interface, data structure, automation, and reporting.
