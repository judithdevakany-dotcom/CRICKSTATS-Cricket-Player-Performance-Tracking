# Phase 6 – Project Testing

## 6.1 Testing Overview

The CRICKSTATS application is tested to verify that the developed Salesforce features work correctly and produce the expected results.

## 6.2 Test Cases

| Test Case | Test Description | Expected Result |
|---|---|---|
| TC-01 | Create a Player record | Player record should be created successfully |
| TC-02 | Create a Match Performance record | Match performance record should be created successfully |
| TC-03 | Check input validation | Invalid data should be prevented |
| TC-04 | Check record type behavior | Records should behave according to the configured settings |
| TC-05 | Check Flow execution | Automated Flow should execute correctly |
| TC-06 | Check Roll-Up Summary | Player statistics should be updated from related performance records |
| TC-07 | Check Reports | Required performance data should be displayed correctly |
| TC-08 | Check Dashboards | Performance information should be displayed visually |
| TC-09 | Check application response | Salesforce pages and features should respond correctly |

## 6.3 Functional Testing

Functional testing is performed for the major CRICKSTATS features:

- Player record creation
- Match Performance record creation
- Data validation
- Record type behavior
- Flow automation
- Roll-Up Summary calculations
- Reports
- Dashboards

## 6.4 Automation Testing

Salesforce Flows are tested to verify that automated processes execute correctly and update the required player statistics.

## 6.5 Data Validation Testing

Player and Match Performance inputs are checked to ensure that incorrect or invalid information is not accepted.

## 6.6 Report and Dashboard Testing

Reports and dashboards are tested to verify that player performance information is displayed correctly and can be used for performance analysis.

## 6.7 Testing Result

The testing phase verifies the main functions of the CRICKSTATS application, including record creation, validation, automation, roll-up summaries, reports, and dashboards.
